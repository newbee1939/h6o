## MCPのアーキテクチャ

MCPのアーキテクチャは、主に以下の3つの要素で構成されている。

- ホスト
    - MCPを利用するアプリケーション本体（e.g. Claude Code, Cursor）
- クライアント
    - ホストの中に立ち上がり、サーバーとのやり取りを行うコンポーネント
    - 1つのサーバーに対して「1対1」で通信を行う
- サーバー
    - ホストやクライアントとは独立して外部で動作する
    - ホスト・クライアントに対してデータや機能を提供する
        - `Resources`: データなど
        - `Prompts`: 固定のメッセージやワークフロー
        - `Tools`: AIが呼び出せる関数

### ステートレスについて

最近仕様変更が入った。MCPがステートレス化に舵を切った。

## MCPの処理の流れを時系列で

事前の`initialize`（初期化ハンドシェイク）がなくなり、全てのリクエストがいきなり目的の処理から開始できるようになったのが最大の特徴です。

```
[ユーザー]         [Host (LLM / アプリ)]            [MCP クライアント]                           [MCP サーバー]
   |                     |                                |                                          |
   | 1. プロンプト入力   |                                |                                          |
   | ------------------> |                                |                                          |
   |                     | 2. プロンプトの解釈と          |                                          |
   |                     |    ツールの必要性判断          |                                          |
   |                     | (※事前に把握しているツールリスト|                                          |
   |                     |   と照らし合わせて推論する)    |                                          |
   |                     |                                |                                          |
   |                     | 3. ツール実行の指示            |                                          |
   |                     | -----------------------------> |                                          |
   |                     |                                | 4. MCPリクエストの構築                   |
   |                     |                                |   (ステートレス仕様)                     |
   |                     |                                |                                          |
   |                     |                                | 5. リクエスト送信 (例: tools/call)       |
   |                     |                                | ---------------------------------------> |
   |                     |                                | ※ _metaに常に以下を同梱                  |
   |                     |                                |   - protocolVersion                      |
   |                     |                                |   - clientCapabilities                   |
   |                     |                                |                                          |
   |                     |                                |                                          | 6. メタデータ検証 &
   |                     |                                |                                          |    ツールの独立実行
   |                     |                                |                                          |    (過去の状態に依存しない)
   |                     |                                | 7. レスポンス (実行結果)                 |
   |                     | 8. 実行結果の受け取り          | <--------------------------------------- |
   |                     | <----------------------------- |                                          |
   |                     |                                |                                          |
   |                     | 9. 結果を踏まえて回答を生成    |                                          |
   | 10. 最終的な回答    |                                |                                          |
   | <------------------ |                                |                                          |
```
